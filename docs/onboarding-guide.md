# Welcome to Claude Code — 5-Minute Guide

## What it is
Claude Code is an AI assistant that works directly inside your project's files and folders — you talk to it in plain English in a terminal window, and it reads and writes real files on your computer instead of just chatting back at you. Think of it as a very fast, very well-read teammate who can read what you've already written, draft new documents, and remember your context — as long as it's saved somewhere it can read again next time.

## What you'll build in your first session
You'll use a ready-made prompt to set up your own version of this workspace for whatever product you're working on. By the end of that first session you'll have: a `CLAUDE.md` file that Claude reads automatically every time you start a new conversation (so you stop re-explaining your product, role, and situation from scratch), a few tracking files (`project.md`, `strategy.md`, `change_log.md`) that hold your working context over time, and — most importantly — Claude will have interviewed *you* about your real situation before writing anything, so what gets built reflects your actual work, not a generic template.

## The 3 habits that matter most

**1. Update CLAUDE.md every session.** It's the one file Claude always reads first, automatically. If it goes stale, Claude starts from an outdated picture of what you're working on — the single biggest thing that makes this setup useful over time is keeping that file current.

**2. Use the AI interview before building anything.** Don't let Claude guess at what you need from a one-line request. A few minutes of it asking you questions up front is what keeps the output specific to your real situation instead of generic and wrong-shaped.

**3. Save everything.** Decisions, research, drafts, even messy notes. If it's not saved in a file, Claude won't remember it in your next session — and neither will you in three weeks.

## The most common mistake
**Mistaking something Claude generated for something a real person actually said.** Claude will sometimes write in someone else's voice on purpose — a "skeptical engineer" reacting to your plan, a hypothetical churned user's complaint — to help you pressure-test an idea before it goes to a real person. That's a practice exercise, not a record of an actual conversation. Before you act on or forward anything like that, ask yourself: *did a real person say this, or did Claude write it to help me think something through?* If it's the latter and Claude didn't label it clearly, ask it to.
